# Контур Local Edition для Windows Server

Это локальная версия планировщика для работы внутри офиса, локальной сети и нескольких VLAN. Программирование, Docker и WSL не нужны.

После установки сервер запускает два адреса:

| Адрес по умолчанию | Назначение | Защита |
| --- | --- | --- |
| `https://planner.kontur.local` | Рабочий планировщик сотрудников | Email и пароль |
| `https://portal.kontur.local` | Клиентский портал по ссылке | Ссылка, PIN и срок действия |

Проекты, файлы, публичные ссылки и переписка хранятся только на вашем Windows Server. Planner и Portal используют разные локальные базы и файловые хранилища.

## Что потребуется

- Windows Server 2019, 2022 или 2025 x64;
- статический IP-адрес сервера;
- права локального администратора;
- 4 ГБ свободной оперативной памяти и от 10 ГБ на диске;
- два DNS-имени, указывающих на один сервер.

Для готового автономного архива интернет во время установки не нужен. Если устанавливать прямо из исходников GitHub, установщик скачает Node.js и npm-пакеты.

## Самая простая установка

### 1. Скачайте архив

На странице GitHub откройте **Releases**, выберите последнюю версию и скачайте файл:

`Kontur-Local-Edition-<версия>-win-x64.zip`

Распакуйте его, например в `C:\Temp\Kontur`.

### 2. Откройте PowerShell от администратора

Нажмите **Пуск**, введите `PowerShell`, нажмите правой кнопкой и выберите **Запуск от имени администратора**.

Выполните команды по одной:

```powershell
Set-ExecutionPolicy -Scope Process Bypass -Force
cd C:\Temp\Kontur
.\distribution\windows-server\Install-Kontur.ps1
```

Установка обычно занимает несколько минут. Она автоматически:

- копирует приложение в `C:\ProgramData\Kontur`;
- создаёт отдельные локальные базы Planner и Portal;
- создаёт HTTPS-сертификат;
- включает автозапуск после перезагрузки;
- открывает в брандмауэре только порты 80 и 443;
- создаёт первого администратора со случайным паролем.

### 3. Получите первый пароль

После установки откройте файл:

`C:\ProgramData\Kontur\FIRST-LOGIN.txt`

Скопируйте пароль в менеджер паролей, затем удалите этот файл.

### 4. Настройте DNS для сотрудников

На внутреннем DNS-сервере создайте две A-записи на IP Windows Server:

- `planner.kontur.local`;
- `portal.kontur.local`.

Если внутреннего DNS нет, эти имена можно временно добавить в файл `C:\Windows\System32\drivers\etc\hosts` каждого компьютера. Укажите реальный IP сервера, а не `127.0.0.1`.

### 5. Доверьте HTTPS-сертификату

Скопируйте с сервера файл:

`C:\ProgramData\Kontur\tls\kontur-root-ca.cer`

Установите его на компьютеры сотрудников в хранилище **Доверенные корневые центры сертификации**.

В домене удобнее распространить сертификат через групповую политику:

**Конфигурация компьютера → Политики → Конфигурация Windows → Параметры безопасности → Политики открытого ключа → Доверенные корневые центры сертификации**.

После этого откройте `https://planner.kontur.local` и введите email и пароль из `FIRST-LOGIN.txt`.

## Несколько VLAN

По умолчанию брандмауэр разрешает подключения из локальных подсетей Windows. Чтобы явно разрешить несколько VLAN, передайте их при установке:

```powershell
.\distribution\windows-server\Install-Kontur.ps1 `
  -AllowedNetworks @("192.0.2.0/24", "198.51.100.0/24")
```

Адреса выше являются учебным примером. Замените их на реальные CIDR-подсети своих VLAN. Межсетевые экраны и маршрутизаторы должны разрешать клиентам TCP 443 до IP сервера. Внутренние порты баз данных наружу не открываются.

Planner и Portal работают на одном IP, поэтому обычный L3-брандмауэр не сможет разделить их только по DNS-имени. Рабочая часть всё равно требует логин и пароль. Для строгого разделения по VLAN понадобятся два IP-адреса или отдельный корпоративный reverse proxy.

## Добавление сотрудника

На сервере откройте PowerShell от администратора:

```powershell
cd C:\ProgramData\Kontur\app\distribution\windows-server
.\Add-KonturUser.ps1 -Email employee@example.test -Name "Новый сотрудник"
```

Скрипт покажет временный пароль. Затем владелец должен открыть раздел **Команда** в планировщике и добавить тот же email с нужной ролью. Передайте пароль сотруднику отдельным сообщением.

Удаление локального доступа:

```powershell
.\Remove-KonturUser.ps1 -Email employee@example.test
```

## Управление сервером

Запускайте команды из `C:\ProgramData\Kontur\app\distribution\windows-server`:

```powershell
.\Status-Kontur.ps1
.\Stop-Kontur.ps1
.\Start-Kontur.ps1
.\Backup-Kontur.ps1
```

Резервная копия включает базы, документы, конфигурацию и HTTPS-ключ. По умолчанию она сохраняется в `C:\ProgramData\Kontur\backups`. Храните архив в защищённом месте.

## Обновление

1. Сделайте резервную копию командой `Backup-Kontur.ps1`.
2. Скачайте и распакуйте новый автономный архив в отдельную временную папку.
3. Запустите новый `Install-Kontur.ps1` от администратора.

Установщик заменит программные файлы, но сохранит локальные базы, документы, пользователей и сертификат.

## Удаление

Сначала отключите сервис, сохранив все данные:

```powershell
.\Uninstall-Kontur.ps1
```

Для полного удаления вместе со всеми проектами и файлами используйте явный параметр:

```powershell
.\Uninstall-Kontur.ps1 -RemoveFiles
```

Полное удаление необратимо. Сначала сделайте резервную копию.

## Где находятся данные

| Путь | Содержимое |
| --- | --- |
| `C:\ProgramData\Kontur\data\planner` | Проекты, команда и внутренние файлы |
| `C:\ProgramData\Kontur\data\portal` | Опубликованные снимки и клиентские файлы |
| `C:\ProgramData\Kontur\config\kontur.json` | Пользователи и настройки сервиса |
| `C:\ProgramData\Kontur\logs` | Журналы запуска и ошибок |
| `C:\ProgramData\Kontur\tls` | HTTPS-сертификат и ключ |

Доступ к корневому каталогу установки ограничивается локальными администраторами и учётной записью SYSTEM.

## Если что-то не работает

Проверьте состояние:

```powershell
C:\ProgramData\Kontur\app\distribution\windows-server\Status-Kontur.ps1
```

Затем откройте журналы:

- `C:\ProgramData\Kontur\logs\kontur-runtime.log`;
- `C:\ProgramData\Kontur\logs\workers.log`.

Частые причины:

- DNS-имена не указывают на IP сервера;
- корневой сертификат не установлен на компьютере;
- маршрутизатор между VLAN не пропускает TCP 443;
- пользователь создан скриптом, но не добавлен владельцем в разделе **Команда**;
- порт 443 уже занят IIS или другой программой.

## Текущие ограничения

- локальная версия использует собственные email/пароли, интеграции с Active Directory/LDAP пока нет;
- почтовые уведомления и внешние интеграции требуют доступа к соответствующим внешним сервисам;
- не публикуйте локальный сервер напрямую в интернет — для внешнего доступа используйте VPN или корпоративный reverse proxy.
