# Развёртывание

## Локальная сеть

Для постоянной работы на Windows Server используйте готовую [Local Edition](../distribution/windows-server/README-RU.md). Она запускает Planner и Portal с отдельными локальными D1/R2-совместимыми хранилищами, настраивает HTTPS, автозапуск и правила брандмауэра. Docker и WSL не требуются.

## Рекомендуемая схема

Разверните `apps/planner` и `apps/portal` как два независимых Cloudflare Worker-приложения.

- Planner: закрытый доступ, собственные D1 и R2.
- Portal: публичный доступ, отдельные D1 и R2.
- Не подключайте одну и ту же базу или корзину к обоим приложениям.

## Подготовка

```bash
npm run setup
npm run check:public
npm run build
```

Для каждого приложения создайте отдельную D1-базу и R2-корзину с логическими привязками `DB` и `BUCKET`. Примените SQL-миграции из соответствующего каталога приложения.

## Настройки Planner

```dotenv
PUBLIC_SHARE_ORIGIN=https://portal.example.com
PUBLIC_SHARE_SECRET=<случайное значение длиной не менее 32 символов>
```

## Настройки Portal

```dotenv
PLANNER_ORIGIN=https://planner.example.com
PUBLISH_SECRET=<то же случайное значение>
```

Origin указывается без завершающего `/`. Для рабочего окружения используйте только HTTPS.

## Порядок публикации

1. Опубликуйте Portal и получите его постоянный HTTPS-адрес.
2. Укажите этот адрес как `PUBLIC_SHARE_ORIGIN` в Planner.
3. Опубликуйте Planner и укажите его адрес как `PLANNER_ORIGIN` в Portal.
4. Настройте одинаковый HMAC-секрет на обеих сторонах.
5. Оставьте Planner закрытым, а Portal откройте публично.
6. Создайте тестовый проект, публичную ссылку и проверьте её в приватном окне браузера.
7. Отзовите тестовую ссылку и убедитесь, что ранее созданная сессия больше не работает.

## Обновления

Перед обновлением сделайте резервные копии D1 и R2. Не изменяйте уже применённые миграции: добавляйте новые. Сначала обновляйте Portal, затем Planner, если описание релиза не требует другого порядка.
