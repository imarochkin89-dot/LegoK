# Запуск Kontur Community Edition с нуля

Эта инструкция рассчитана на человека, который раньше не разворачивал приложения. Команды можно копировать по одной. Знать программирование не требуется.

## Что именно запускается

В проекте два отдельных приложения:

| Приложение | Для чего нужно | Доступ |
| --- | --- | --- |
| **Planner** | Проекты, задачи, документы, бюджет и внутренняя работа | Закрытый |
| **Portal** | Выбранные этапы, документы и обратная связь для клиентов | Публичный |

Сначала выберите подходящий вариант:

1. **Хочу просто посмотреть проект на своём компьютере** — используйте раздел A.
2. **Хочу получить постоянные адреса в интернете** — используйте раздел B.
3. **Хочу установить проект на Windows Server внутри организации** — откройте [инструкцию Local Edition](../distribution/windows-server/README-RU.md).

## A. Запуск на компьютере с Windows

Такой запуск подходит для знакомства с интерфейсом и демонстрационными данными. Компьютер будет выполнять роль временного сервера, поэтому после закрытия окон PowerShell проект остановится.

### Шаг 1. Установите две программы

Установите:

- [Node.js](https://nodejs.org/) версии **22.13 или новее** — на сайте выбирайте вариант LTS;
- [Git for Windows](https://git-scm.com/download/win).

После установки закройте и снова откройте PowerShell.

Проверьте установку тремя командами:

```powershell
node --version
npm --version
git --version
```

Каждая команда должна показать номер версии. Если Windows пишет, что команда не найдена, перезагрузите компьютер и повторите проверку.

### Шаг 2. Скачайте проект

Самый простой способ:

1. Откройте главную страницу репозитория.
2. Нажмите зелёную кнопку **Code**.
3. Выберите **Download ZIP**.
4. Распакуйте архив, например в `C:\Kontur`.

Можно использовать Git вместо ZIP:

```powershell
cd C:\
git clone https://github.com/USERNAME/LegoK.git Kontur
cd C:\Kontur
```

Замените `USERNAME` на имя владельца репозитория. Точный адрес можно скопировать через **Code → HTTPS** на странице проекта.

### Шаг 3. Откройте PowerShell в папке проекта

Откройте распакованную папку в Проводнике, нажмите на адресную строку, введите `powershell` и нажмите Enter.

В открывшемся окне выполните:

```powershell
npm run setup
```

Установка может занять несколько минут. Предупреждения с текстом `warn` обычно не мешают работе. Если появилась строка `npm ERR!`, посмотрите раздел «Частые проблемы» ниже.

### Шаг 4. Создайте локальные настройки

В том же окне выполните:

```powershell
Copy-Item apps\planner\.env.example apps\planner\.env
Copy-Item apps\portal\.env.example apps\portal\.env
```

Примеры уже настроены на локальные адреса. Для первого запуска менять их не нужно.

### Шаг 5. Запустите Planner

Выполните:

```powershell
npm --prefix apps/planner run dev
```

Не закрывайте это окно. Откройте в браузере:

<http://localhost:4173>

### Шаг 6. Запустите Portal

Откройте **второе** окно PowerShell в папке проекта и выполните:

```powershell
npm --prefix apps/portal run dev
```

Не закрывайте и это окно. Публичный портал будет доступен по адресу:

<http://localhost:4174>

Чтобы остановить приложения, нажмите `Ctrl+C` в каждом окне PowerShell.

> Локальный запуск предназначен прежде всего для просмотра интерфейса. Постоянное хранение данных, совместная работа, загрузка файлов и полноценные публичные ссылки требуют D1, R2 и размещения в интернете.

## B. Публикация через ChatGPT Sites — рекомендуемый вариант

Это самый простой способ получить работающую версию в интернете. ChatGPT создаст два отдельных сайта, базы данных и файловые хранилища.

### Шаг 1. Подготовьте GitHub

Если вы хотите изменять проект, сделайте собственную копию:

1. Откройте главную страницу этого репозитория.
2. Нажмите **Fork**.
3. Подтвердите создание копии в своём аккаунте.

Подключите приложение GitHub в ChatGPT и разрешите ему доступ к вашей копии репозитория. Если репозиторий не отображается, установите [ChatGPT Codex Connector](https://github.com/apps/chatgpt-codex-connector/installations/new) и выберите нужный репозиторий.

### Шаг 2. Отправьте ChatGPT готовый запрос

Создайте новый чат и вставьте текст ниже. Замените ссылку на адрес своей копии, если сделали Fork.

```text
Используй GitHub и Sites. Возьми Kontur Community Edition из репозитория
https://github.com/USERNAME/LegoK

Разверни два отдельных приложения:
1. apps/portal — отдельный публичный клиентский портал;
2. apps/planner — отдельный закрытый планировщик.

Для каждого приложения создай собственные D1 и R2. Не подключай одну базу
или одно файловое хранилище к обоим приложениям. Примени миграции из
репозитория. Создай новый случайный секрет длиной не менее 32 символов и
настрой одинаковое значение как PUBLIC_SHARE_SECRET в Planner и
PUBLISH_SECRET в Portal. Свяжи приложения через PUBLIC_SHARE_ORIGIN и
PLANNER_ORIGIN, используя их постоянные HTTPS-адреса без завершающего слеша.

Planner оставь закрытым. Portal опубликуй для доступа по клиентским ссылкам.
Перед публичной публикацией покажи, какая часть будет открыта, и запроси моё
подтверждение. После развёртывания дай две ссылки и проведи проверку создания
и отзыва тестовой публичной ссылки.
```

ChatGPT может задавать вопросы о доступе к GitHub или публичной публикации. Подтверждайте только доступ к нужному репозиторию и публикацию **Portal**. Planner должен оставаться закрытым.

### Шаг 3. Сохраните результат

После завершения у вас будут два адреса:

- закрытый адрес Planner — для сотрудников;
- публичный адрес Portal — основа для клиентских ссылок.

Сами по себе секреты запоминать не нужно, но не публикуйте их в GitHub и не отправляйте посторонним.

### Шаг 4. Проверьте работу

1. Откройте Planner.
2. Создайте тестовый проект и одну задачу.
3. Опубликуйте задачу в клиентском портале.
4. Создайте публичную ссылку и PIN-код.
5. Откройте ссылку в приватном окне браузера.
6. Проверьте, что внутренние данные Planner не видны.
7. Отзовите ссылку в Planner.
8. Обновите клиентскую страницу и убедитесь, что доступ закрыт.

## Частые проблемы

### `node`, `npm` или `git` не является командой

Программа не установлена либо Windows ещё не обновила системный путь. Установите её, закройте PowerShell и откройте заново. Если не помогло — перезагрузите компьютер.

### PowerShell не находит `package.json`

Команда запущена не из корневой папки проекта. Перейдите в неё:

```powershell
cd C:\Kontur
```

Затем повторите `npm run setup`.

### При установке появился `npm ERR!`

Убедитесь, что Node.js имеет версию 22.13 или новее:

```powershell
node --version
```

После этого повторите установку из корневой папки:

```powershell
npm run setup
```

### Браузер не открывает `localhost:4173` или `localhost:4174`

Проверьте, что оба окна PowerShell остаются открыты и в них нет сообщения об ошибке. Используйте `http://`, а не `https://`.

### GitHub подключён, но ChatGPT не может записать файлы

Авторизация аккаунта и установка приложения — разные действия. Откройте [страницу установки коннектора](https://github.com/apps/chatgpt-codex-connector/installations/new), выберите свой аккаунт и разрешите доступ к нужному репозиторию.

### Planner не создаёт публичную ссылку

Чаще всего приложения не связаны между собой. Проверьте:

- `PUBLIC_SHARE_ORIGIN` содержит адрес Portal;
- `PLANNER_ORIGIN` содержит адрес Planner;
- `PUBLIC_SHARE_SECRET` и `PUBLISH_SECRET` имеют одинаковое значение;
- адреса начинаются с `https://` и записаны без `/` в конце.

### Не получается разобраться с ошибкой

Скопируйте сообщение об ошибке целиком и отправьте его в ChatGPT вместе со ссылкой на репозиторий. Не прикладывайте файл `.env` и не вставляйте секреты.

## Короткий словарь

| Термин | Простое объяснение |
| --- | --- |
| Node.js | Программа, которая запускает проект |
| npm | Устанавливает необходимые части проекта и выполняет команды |
| GitHub | Место, где хранится исходный код |
| D1 | База данных для проектов, задач и настроек |
| R2 | Хранилище загружаемых файлов |
| Secret | Общий закрытый ключ для безопасной связи двух приложений |
| Fork | Ваша собственная копия репозитория на GitHub |

Если нужна техническая схема или ручная публикация через Cloudflare, откройте [расширенное руководство](DEPLOYMENT.md).
