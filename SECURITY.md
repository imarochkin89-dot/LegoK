# Политика безопасности

## Поддерживаемая версия

Исправления безопасности выпускаются для актуальной ветки `main` и последнего опубликованного релиза.

## Сообщение об уязвимости

Не публикуйте сведения об уязвимости в обычном Issue. Используйте приватный отчёт через раздел **Security → Advisories → Report a vulnerability** репозитория.

Укажите:

- затронутый компонент и версию;
- условия воспроизведения;
- возможное влияние;
- минимальный пример без реальных пользовательских данных.

## Важные ограничения

- Планировщик должен быть закрыт средствами платформы или доверенного прокси.
- Заголовки идентификации пользователя считаются доверенными только после удаления одноимённых заголовков, пришедших непосредственно от клиента.
- Публичный портал должен использовать отдельные D1 и R2.
- Значения `PUBLIC_SHARE_SECRET` и `PUBLISH_SECRET` должны совпадать, содержать не менее 32 случайных символов и храниться только в менеджере секретов среды выполнения.
- Смена секрета разрывает управляющую связь между приложениями до синхронного обновления обеих сторон.
