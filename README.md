# Kontur Community Edition

Открытая версия проектного планировщика «Контур» с отдельным клиентским порталом. Репозиторий содержит только исходный код, демонстрационные записи и шаблоны конфигурации. Производственные данные, документы, ссылки доступа и ключи в него не входят.

## Возможности

- проекты, канбан-доска, сроки, зависимости и диаграмма Ганта;
- бюджет, трудозатраты, риски, ресурсы и файлы;
- команда, роли, комментарии, уведомления и отчёты;
- PWA-режим и локальная работа интерфейса;
- отдельный публичный портал по ссылке и PIN-коду;
- портфель из нескольких проектов в одной клиентской ссылке;
- опубликованные документы, согласование этапов, обратная связь и лента обновлений;
- отзыв ссылок, смена PIN и ограничение срока действия.

## Состав

| Каталог | Назначение | Рекомендуемый доступ |
| --- | --- | --- |
| `apps/planner` | Рабочее пространство команды и административные API | Закрытый |
| `apps/portal` | Публичная витрина выбранных данных | Публичный |

Приложения используют отдельные D1-базы и R2-хранилища. Между ними передаются только специально опубликованные данные. Управляющие запросы подписываются HMAC, поэтому один и тот же секрет должен быть настроен в обоих приложениях.

## Требования

- Node.js 22.13 или новее;
- npm;
- среда Cloudflare Workers с D1 и R2;
- для текущего адаптера авторизации — ChatGPT Sites или доверенный прокси, формирующий заголовки пользователя.

## Быстрый старт

```bash
npm run setup
npm run check:public
npm run build
```

Запуск интерфейса планировщика:

```bash
npm --prefix apps/planner run dev
```

Запуск клиентского портала:

```bash
npm --prefix apps/portal run dev
```

Локально доступны демонстрационные проекты. Совместная работа, загрузка файлов и управление публичными ссылками требуют D1, R2 и доверенной идентификации пользователя.

## Переменные окружения

В рабочем приложении:

```dotenv
PUBLIC_SHARE_ORIGIN=https://portal.example.com
PUBLIC_SHARE_SECRET=replace-with-at-least-32-random-characters
```

В клиентском портале:

```dotenv
PLANNER_ORIGIN=https://planner.example.com
PUBLISH_SECRET=replace-with-the-same-random-value
```

Для локального запуска скопируйте `.env.example` в `.env` внутри каждого приложения: шаблоны уже используют порты 4173 и 4174. Для публикации замените origin на постоянные HTTPS-адреса. Секрет можно создать командой `openssl rand -hex 32`. Не добавляйте `.env` и рабочие значения в Git.

Подробности находятся в [руководстве по развёртыванию](docs/DEPLOYMENT.md) и [описании архитектуры](docs/ARCHITECTURE.md).

## Безопасность и приватность

- рабочий планировщик должен оставаться закрытым;
- публичный портал разворачивается отдельно и не подключается к рабочей базе;
- наружу попадают только выбранные этапы и опубликованные документы;
- PIN-код не заменяет контроль содержимого публикации;
- перед каждым релизом запускайте `npm run check:public`.

Уязвимости следует передавать непублично через GitHub Security Advisories. Подробности — в [SECURITY.md](SECURITY.md).
